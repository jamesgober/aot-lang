# aot-lang v1.0.1 — object code you can read back

**A correctness patch.** `1.0.0` wrote object code that lost every jump target, so no function with a branch or a loop could be recovered from an image. This release adds the missing label table under a versioned header, corrects the documentation that called the encoding lossless and the image loadable, and raises the codegen-lang floor to the release that fixes its loop miscompile. There is no public API change. The byte format changes deliberately; the reason is below.

**Everyone on `1.0.0` should upgrade.** Its images were complete only for straight-line functions.

## The bug (ISSUES H02)

codegen-lang's bytecode jumps to **label ids**, not op indices. A `Program` carries a label table that maps each id to the op it starts at. `1.0.0`'s encoder wrote the register count, the parameters, and the ops, but not that table:

```text
1.0.0 record:   register_count  param_count  params…  op_count  ops…
                                                                 └─ jump L3, jump_unless r5 L2 …   // L3 = ? L2 = ?
```

Nothing in the image says which op `L3` is. For the `if`/`else` in `max` or the back edge of `sum_to`, the bytes are a program with unresolvable targets. Meanwhile the module docs said "the encoding is lossless", and the crate docs and README said the image was "ready to be … loaded". There is no loader in aot-lang, and the bytes could not have supported one.

## The fix

Each function is now one self-describing record, **format version 1**:

```text
magic "AOTB" · version 1 · register_count · param_count · params… ·
label_count · labels… (label i → op index) · op_count · ops…
```

- **The label table** holds every label id the program defines, in id order, so every `jump`/`jump_unless` target resolves from the record alone. The op stream is unchanged from codegen-lang's `Program`, so the record is lossless and a reader can rebuild the exact program.
- **The magic and version** let a reader refuse what it does not understand. `1.0.0`'s headerless layout counts as version 0. It begins with a register count, not `AOTB`, so a version-1 reader rejects it at the magic instead of misreading it.
- The full layout, including op tags and operator codes, is now specified in [`docs/API.md`](../API.md#object-code-format). Before, it was only in a private module's rustdoc.
- Counts are narrowed to `u32` with saturation instead of `as u32`. They are bounded by `u32` upstream, and a record that somehow exceeded the bound fails to decode rather than aliasing a smaller count.

**Size:** a record grows by 12 bytes (magic, version, label count) plus 4 bytes per label. A function has one label per block plus a few internal ones.

### Why a format change is a patch

The `1.0` SemVer promise said "the object-code bytes for a given program are stable". That promise covered bytes that could not represent control flow. Keeping them stable would have kept them broken. The format change is the bug fix, and it is recorded under **Fixed** in the CHANGELOG. The promise now reads "stable within a format version": any future layout change bumps the version and is called out.

## codegen-lang 1.0.1 (ISSUES H01)

aot-lang lowers every function through codegen-lang. codegen-lang `1.0.0` miscompiled loop back edges that pass a header's own parameters in a different order. For example, `jump H(b, a)` left both registers holding `b`. aot-lang's images inherited the miscompile. The requirement is now `codegen-lang = "1.0.1"` (was `"1"`), so an aot-lang `1.0.1` build cannot resolve to the broken lowering. Op streams differ from `1.0.0` only for functions with such an edge.

## What aot-lang still is not

aot-lang produces images. It does **not** load or run them, and `1.0.1` adds no public decoder: a decoder would be new API, which a patch cannot add. A reader is shipped **tests-only**, as described below, and the format is documented so one can be written. If a public decoder is wanted in `1.x`, it is a minor release. Long-term, this bytecode container is superseded by the native AOT path in Phase 5 of the LexerSketch roadmap: our own backend, then object-lang, then the linker, then a real executable.

## Tests added

- **Tests-only decoder** (`tests/support/decode.rs`). The unit tests compile it from the same file. It states the format independently of the encoder: tags and widths are written from the spec, not imported. Every read is checked, every count is bounded by the bytes remaining (a claimed four billion labels is refused without allocating), and it refuses bad magic, unknown versions, unknown tags, truncation, and trailing bytes.
- **Round-trip through the image** (`tests/format.rs`). Functions are read back out of linked images by symbol and compared with the program codegen-lang lowered: name, register count, parameters, the full label table, and every op, with float constants compared by bit pattern. codegen-lang 1.0 has no public `Program` constructor or `labels()` accessor, so the comparison reads the program through its public accessors (`label_offset` for every id). It includes a property over arbitrary generated control-flow graphs: 1 to 6 blocks, loops, back edges passing arguments in any order, several functions per image, and an arbitrary base address. It also checks that every decoded jump target resolves inside its record, that records tile `.text` exactly, and that `1.0.0`-layout bytes are refused.
- **End to end** (`tests/execute.rs`). Functions are decoded from the image, run by a test interpreter, and compared with a direct IR evaluation. Covered: `sum_to`, `fib`, a swap back edge, a 3-cycle rotation, all four in one image at a nonzero base; a property over counted loops (0–12 trips) whose back edges permute, rotate, duplicate, and offset 2–5 variables; and a property over arbitrary CFGs, compared whenever the IR evaluation ends within its budget (about 56% of generated cases; the rest loop past it). A coverage test requires at least a fifth of generated CFGs to contain a backward jump.
- **Mutation checks.** With codegen-lang pinned back to `1.0.0`, the swap, rotation, all-loops, and permuting-loop tests fail. The proptest seed that found it is kept in `tests/execute.proptest-regressions` and replays on every run. With the label table left out (`label_count` forced to 0), 9 unit tests, all 8 `execute` tests, and 4 of 6 `format` tests fail. The 2 that still pass test byte-level refusal, not round-trips.
- **Unit tests** cover the header, the label table of a branch, NaN payloads, each truncation length, hostile counts, and the `1.0.0` layout, plus a property that the decoder is total on arbitrary bytes.

## Performance

Criterion on one Windows x86-64 machine, `1.0.1` against the `1.0.0` encoder (both with codegen-lang 1.0.1). The machine was noisy: identical code measured 19.2–23.0 µs for `link/sixteen_functions` across consecutive runs.

| Bench | 1.0.0 encoder | 1.0.1 (three runs) |
|---|---:|---:|
| `compile/arith_depth_64` | 2.28 µs | 2.41–3.39 µs |
| `compile/counting_loop` | 1.92 µs | 2.10–2.27 µs |
| `link/sixteen_functions` | 19.7 µs | 19.3–23.0 µs |

The added work is a linear walk of the label table and 12 + 4·labels extra bytes per function. No difference outside the noise band could be established on this machine.
